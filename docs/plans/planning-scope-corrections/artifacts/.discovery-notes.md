# Discovery Notes: Planning Scope Corrections

Project context gathered before the implementation-planning team was launched. Every specialist reads this first and
does not re-search for what is already here.

## Tech stack

Han is a Claude Code plugin suite. There is no application runtime, no build, and no test runner. The "code" is
markdown: skill definitions (`{plugin}/skills/{name}/SKILL.md`), agent definitions (`{plugin}/agents/{name}.md`),
reference files (`{plugin}/references/*.md` and `{plugin}/skills/{name}/references/*.md`), long-form docs
(`{plugin}/docs/skills/{name}.md`), and JSON manifests (`{plugin}/.claude-plugin/plugin.json`,
`{plugin}/.codex-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.agents/plugins/marketplace.json`).

Shipping a change means editing prompt text and manifests. Verification is by reading and by running the changed skill,
not by an automated suite. No CI test job exists that exercises skill behavior.

## Architectural decisions found

- `docs/adr/0001-project-configurable-default-swarm-size.md` — the `.han/config.md` project-config mechanism, its
  precedence rules, and the containment rule that keeps config interpretation in one canonical
  `config-rule.md` vendored byte-identical into each skill-carrying plugin.

No other ADRs exist. There is no ADR governing where a cross-skill convention lives, which is a gap this change has to
settle for itself (see the reference-home question below).

## Standards and conventions found

- `CLAUDE.md` (repo root) — the project map. Names every plugin, its dependencies, its layout, and the documentation
  conventions: one canonical source per concept, every long-form doc links up, uniform voice, YAGNI applies to docs,
  and indexes stay complete rather than counted.
- `CONTRIBUTING.md` — the contributor guide. Lines 195-215 carry the four-step procedure for wiring the readability
  standard into a new reader-facing skill: declare the `han-communication` dependency, embed the structural rules in
  the output template, source the standard at the drafting point, and add the standardized self-check. This is the
  named precedent for how a new shared communication standard gets delivered.
- `han-plugin-builder/skills/guidance/references/` — the authoring guidance. `plugin-entity-taxonomy.md` (skill vs.
  agent vs. hook), `skill-building-guidance/`, `agent-building-guidelines/`, `per-model-authoring.md`,
  `specialization-and-model-selection.md`, `templates/`. Any new skill or reference file this change adds is authored
  against this guidance, per `CLAUDE.md`'s standing instruction.
- `docs/readability.md#scope-which-skills-are-reader-facing` — the authoritative enumerated list of reader-facing
  skills. A new reader-facing skill is added there.
- `docs/configuration.md`, `han-core/references/config-rule.md` — the config contract.

## Recent activity

Ninety days of churn concentrates exactly on the files this change touches. `plan-work-items/SKILL.md` and
`plan-implementation/SKILL.md` lead at ten commits each; `plan-a-feature/SKILL.md` eight;
`plan-a-phased-build/SKILL.md` and `iterative-plan-review/SKILL.md` seven each; both `han-communication` skills six
each; `han-feedback/SKILL.md` five. `han-planning/.claude-plugin/plugin.json` moved nine times, so plugin versions are
bumped routinely alongside skill edits.

Two implications. These files are actively edited, so a plan that lands as one enormous simultaneous rewrite conflicts
with how the repo actually moves. And the per-skill long-form docs move with their skills, which confirms the
documentation obligation is routine here rather than exceptional.

## Format precedent

`docs/plans/` holds twenty-three prior plan folders. Recent ones with the current three-file layout
(`feature-implementation-plan.md` at the root, `artifacts/implementation-decision-log.md`,
`artifacts/implementation-iteration-history.md`) include `han-communication-plugin`, `readability-in-planning-coding`,
`plugin-centric-docs-reorg`, and `reduce-context-footprint`. Those are the level-of-detail precedent.

Note: `docs/plans/CLAUDE.md` instructs that plan folders are not read or modified except when a skill or the user
directs it. This run is directed at `docs/plans/planning-scope-corrections/`, so that folder is in scope and the
others are read only as format precedent.

## Gaps: searched for and not found

- **No automated test suite for skill behavior.** Searched for test runners, CI workflows exercising skills, and
  lint/validation scripts over SKILL.md files. None exist. Verification of every commitment in this spec is by reading
  the changed prompt and by running the skill. Any plan that assumes a test gate is assuming something absent.
- **No ADR on where a cross-skill convention lives.** Only ADR 0001 exists, and it covers config. D24 places the
  visual-material convention in `han-planning/references/`, and F23 flags that the reconciled missing-artifact rule
  has no named home. There is no prior decision to lean on, so the plan settles it.
- **No coding-standards directory.** No `docs/coding-standards/` and no `.github/CODING_STANDARDS.md`. The authoring
  rules live in `han-plugin-builder/skills/guidance/references/` instead.
- **No `.han/config.md` in this repo.** The probe returned nothing. No project config applies to this run.
- **No `project-discovery.md`.** The probe returned nothing; `CLAUDE.md` carries the project map instead.
