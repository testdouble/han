# Discovery Notes: Personal Han Configuration

Project context gathered before dispatching the implementation team. Read this first; do not re-grep for what is here.

## Tech stack

- Content is Markdown: skill definitions (`{plugin}/skills/{name}/SKILL.md`), agent definitions, reference files, and
  operator docs. Bash lives only in skill `scripts/`.
- Package manager: npm. `package.json` manages dev tooling only. No application build, no dev server.
- Install: `npm install` (prek, Prettier, Bats, all local, nothing on the global PATH).
- Lint: `npm run lint` runs `prek run --all-files` (Prettier, ShellCheck, file hygiene).
- Test: `npm test` runs Bats over every `*.bats` outside `node_modules`. Script tests sit beside the script; `test/`
  holds harness-level checks only (`test/sanity.bats` is a 2+2 smoke test).
- Existing Bats coverage is per-script only, in four skills. Nothing today tests SKILL.md content or probe behavior.

## Documented incident the probe change must respect

`docs/plans/fix-config-probe-exit-code/` records a shipped bug: the probe originally read
`cat .han/config.md 2>/dev/null`, which exits 1 when the file is absent. The Claude Code skill loader treats a nonzero
exit from a backtick context probe as a hard failure, so **every Han skill aborted in every project without the optional
file**. The fix added `|| echo ""` across all 39 SKILL.md files then present.

Two constraints follow, and they are the highest-risk part of this work:

1. Any new probe line must always exit 0.
2. The investigation recorded that the loader auto-approves only certain command shapes. `|| true` was explicitly
   refuted during that work because `true` is not on the allowlist; `2>/dev/null || echo ""` was chosen because it was
   already proven by fifteen-plus working probes in the suite. A personal-config probe needs to resolve an environment
   variable with a fallback, which is a shape the suite has never shipped.
